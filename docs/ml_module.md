# ML/NLP Module

## Role and current scope

The ML module classifies a review as positive or negative and returns model evidence for the downstream priority engine. It does not assign HIGH, MEDIUM, or LOW priority. The larger project still needs Kafka, HDFS, and dashboard integration; this classifier alone is not the complete big-data system.

## Dataset and labels

The local sample is the first 200,000 JSONL records from the Amazon Reviews 2023 Appliances category:

`https://huggingface.co/datasets/McAuley-Lab/Amazon-Reviews-2023/resolve/main/raw/review_categories/Appliances.jsonl`

The downloaded file belongs at `data/raw/appliances_sample.jsonl`. Raw and processed data are ignored by Git. The project does not commit the dataset or fitted model artifact.

Ratings are converted to binary labels as follows:

- Ratings 1–2: negative (`label=1`).
- Ratings 4–5: positive (`label=0`).
- Rating 3: excluded as neutral.

Text is HTML-unescaped, common HTML tags and media markers are removed, whitespace is normalized, and common contractions are expanded to preserve negation (for example, “isn't” becomes “is not”). Stop words and punctuation are not removed during normalization.

The 200,000-row sample contained 10,607 neutral reviews. Among the eligible, non-empty binary-labeled reviews, 70 normalized review texts appeared with both labels (2,013 rows). All rows belonging to those conflicting text groups were removed. Remaining repeated normalized texts were reduced to one row so identical reviews cannot cross split boundaries. This retained 170,671 unique labeled reviews.

## Reproduce the ML workflow

Run these commands from the repository root in the WSL Ubuntu virtual environment:

```bash
source ~/venvs/bda-ml/bin/activate
python src/ml/prepare_data.py
python src/ml/train.py
python src/ml/evaluate_thresholds.py
python src/ml/evaluate.py
pytest -v
```

`prepare_data.py` uses seed 42 and stratifies a 70/15/15 train/validation/test split. Current split sizes are 119,469 / 25,601 / 25,601. The class proportions are approximately 86.96% positive and 13.04% negative in each split. Generated CSV files are written to `data/processed/` and ignored by Git.

The TF-IDF vectorizer is fitted only on training data. Validation data was used to compare decision thresholds. The test split was kept out of training and threshold selection and used once for final evaluation.

## Baseline model

The saved scikit-learn Pipeline contains:

- Text normalization through the project's `normalize_text` function.
- TF-IDF word unigrams and bigrams (`min_df=2`, `max_df=0.95`, up to 100,000 features, sublinear term frequency).
- Logistic Regression with balanced class weights and a fixed seed (42).

Balanced class weights give the smaller negative class more influence during fitting. The fitted pipeline is saved locally as `models/sentiment_pipeline.joblib`; the model includes its vectorizer so inference uses the same vocabulary and transformations. It is generated by `train.py` and ignored by Git.

## Threshold choice and final results

The classifier's default probability cutoff of 0.50 gave 89.49% negative recall on validation. Lowering the negative threshold to 0.45 raised validation recall to 91.61%, with 62.33% negative precision, 1,849 positive reviews flagged as negative, and 280 negative reviews missed. A 0.70 threshold had the highest validation negative F1 among the examined candidates (0.8031), but recall fell to 78.41%. The selected 0.45 threshold favors catching complaints while limiting false alarms to about 8.3% of actual positive reviews on validation. It remains configurable in `predict_review`.

Final held-out test metrics at threshold 0.45:

| Metric | Result |
|---|---:|
| Accuracy | 0.9135 |
| Negative precision | 0.6122 |
| Negative recall | 0.9179 |
| Negative F1 | 0.7345 |
| Inference time for 25,601 reviews | 1.60 seconds |
| Inference throughput | 16,047 reviews/second |

Confusion matrix, rows=actual and columns=predicted, with labels 0=positive and 1=negative:

```text
                 predicted positive  predicted negative
actual positive              20,322               1,941
actual negative                 274               3,064
```

The model caught 91.79% of actual negative reviews in the held-out sample. It missed 274 negative reviews and incorrectly flagged 1,941 positive reviews as negative. This tradeoff should be reviewed with the team before production use. Confidence values are model probabilities and are not calibrated certainty estimates. Inference timing depends on the machine and environment.

## Prediction and keywords

Load the model once when a consumer starts, then reuse it:

```python
from src.ml.predict import load_model, predict_review

model = load_model()
result = predict_review("The battery stopped working after two days.", pipeline=model)
print(result)
```

The result includes `sentiment`, `confidence`, `negative_score`, `threshold`, `keywords`, `error`, and `keyword_error`. Missing and empty text return structured errors. Keyword extraction failures are reported separately from sentiment failures. Keywords are returned for negative predictions only.

`src/nlp/keyword_extractor.py` ranks known TF-IDF unigrams and bigrams from the review and preserves negation phrases such as “not working.” It is an explainable heuristic: extracted terms are not guaranteed to be genuine complaints, and terms absent from the fitted vocabulary cannot be returned.

## Tests and dependencies

Run `pytest -v` from the repository root. The automated tests cover text preprocessing and label conversion, prediction output and invalid inputs, and keyword phrase behavior. Package versions are pinned in `requirements.txt`.
